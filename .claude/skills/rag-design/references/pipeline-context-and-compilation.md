# Ground stages and compile reviewed knowledge

## Distinguish the consumer mechanisms

This method covers exact semantic stage context, a trusted static capability registry, relevance-selected compilation evidence and deterministic reviewed-query overlays. Optional pattern/example memory is a separate construction requiring complete producer-to-prompt wiring. These mechanisms need not all use embeddings or a document store.

Admission → exact/whole-unit preparation → selected evidence or direct lookup → bounded advisory stage context or compiler bundle → validated candidate artifacts → review/current publication. No paragraph windowing is used. Exact-ID loads, static registry lookups and reviewed overlays use no embeddings; optional relevance selection declares lexical/dense representations separately.

## Build advisory stage context

Load a current admitted dataset snapshot with field meaning, metric contracts and observed profiles. Combine it with typed resolved intent/entities, selected analytical strategy and stage-specific trusted capability rules. Validate identities and generation before generating any advisory brief.

```json
{
  "consumer": "query-planning",
  "task": "Compare average order size by region",
  "dataset": "orders",
  "edition": "edition-2",
  "resolved_entities": [],
  "metric": {"aggregation": "weighted_mean", "numerator": "amount_sum", "denominator": "order_count", "population": "admitted filtered orders"},
  "required_output": {"goal": "string", "actions": "bounded string array", "avoid": "bounded string array"}
}
```

The metric contract is illustrative and must be justified by the source. Nonadditivity or numeric type alone does not imply this aggregation. Validate stage keys, array bounds and references to real fields; a generation temperature setting does not guarantee determinism or correctness.

Insert generated advice as labeled advisory data. System policy, admitted source scope, resolved entities, validated SQL/result contracts and role mappings outrank it. Validate and safely serialize every field rather than escaping only the goal. If an optional brief is missing or fails, expose the skip and preserve the governing contract; do not imply the stage was grounded by a brief it never received.

## Keep static capability rules separate

A versioned trusted registry may select chart, operation or query-construction rules by stage and shape. This is direct lookup rather than tenant evidence retrieval or automatic learning. Store registry version, selection key and allowed consumer. A caller-provided block is not automatically trusted registry content. Customer business meaning remains a distinct data source.

## Select evidence for compilation

Intersect requested datasets with authenticated scope, current readiness and intended role. Preserve per-dataset fairness when one prolific source could dominate. Historical sessions may be relevant context, but prior model narratives are unreviewed evidence unless explicitly approved. Bound and sanitize retained history under policy without making it perpetual authority.

A neutral context item is `{resource, edition, unit_key, kind, text, text_digest, provenance, scores, review}`. Whole semantic rows/facets and complete reviewed queries preserve lineage; there is no need to create arbitrary new text windows.

If capability search is required, encode the requested capabilities with a compatible query encoder. Combine broad authorized lexical candidates with separately retrieved dense candidates if lexical rescue matters. Calibrate recency, role, shape and relevance scores rather than copying unexplained weights. Partial channel errors must remain visible even if another channel succeeds.

Deduplicate by stable identity, reject unknown field references, choose section budgets/diversity and record drop reasons. Use stable ties independent of trace IDs when deterministic output is required. Masking selected classified fields is not proof all free text is safe; validate processor policy and minimize samples before context construction.

## Compile and validate candidate artifacts

The compiler input separates trusted runtime contract and static rules from untrusted source evidence, history and requested capabilities. Bind every included item to a source/edition and exact digest. Calculate full input/output/byte/file budgets using the actual runtime constraints. A local evidence budget alone does not guarantee complete-message fit.

Define required files/sections, native target identity, path rules, schema version and structured failure outputs. If generation returns partial bytes, preserve them for recovery only under policy; partial retention is not a ready compile. Recovered output must pass the same validator as first-attempt output.

Build an immutable candidate file tree with content hashes and a deterministic tree digest. Validate path containment, required files, internal links, types and completeness. Review the candidate, then update a current pointer with expected revision after rechecking current source/scope/knowledge bindings. Delete-then-insert replacement is not an atomic tree publication. A content hash establishes byte identity, not truth or approval.

## Add reviewed queries deterministically

Promotion begins with an owned complete SQL-bearing result and explicit review. Canonicalize SQL under a declared policy that preserves semantics; naïve whitespace/literal rewriting may not. Store canonical query identity, input/result contract, population/grain/metric behavior, triggers, source/edition and reviewed disposition.

A role-local slug can route the reviewed artifact. Same slug plus different query identity is a conflict; identical reviewed content may replay idempotently. Match overlays to existing exportable query spines under explicit keys. An unmatched reviewed record does not create a phantom script. Retired or revoked records stay excluded. This relational overlay uses no embedding or model and is not automatic learning.

## Construct optional pattern memory end to end

Pattern memory needs an extraction contract, reviewed scoped storage, current-schema validation, retrieval API, selected-example validator and actual downstream prompt insertion. A writer or declared variable alone does not implement the consumer. Keep caller argument/result shapes and stored schema aligned with executable seam checks.

Regex normalization may replace literals accidentally or make order-dependent substitutions; a parsed SQL representation is safer when semantic structure matters. Preserve canonical originals and explicit placeholders. A normalized successful query is still not automatically safe, reviewed or applicable to another dataset.

Until every join is built, label the path unavailable or proposed. Any repaired reader must return bounded source/edition/contract-bound examples, and the consumer must prove they enter its final manifest as untrusted demonstrations beneath current policy. No historical query changes authority.

## Lifecycle and verification

Revocation invalidates selected evidence, reviewed overlays, compiled pointers and cached contexts. Keep exact-value serialization distinct from display sanitization. An instruction embedded in metadata/history cannot override the read-only or source policy even if it survives a hash.

C7/C8 in `../scripts/verify_contracts.py` check actual-context provenance, expected-revision publication, reviewed overlay conflict and ambiguous retry state. They do not execute a compiler, SQL canonicalizer or model. Additional implementation checks need a nonadditive metric through the real stage consumer, missing brief skip, partial channel failure, deterministic tree output, retained-but-invalid partial compile, unmatched overlay and a pattern stored without any prompt consumer. Judge evidence relevance, structural artifact readiness and final analytical correctness separately.
