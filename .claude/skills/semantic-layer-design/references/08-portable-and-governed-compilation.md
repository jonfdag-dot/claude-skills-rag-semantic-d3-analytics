# Compile portable context under explicit authority

Read this when producing a portable knowledge bundle or designing reviewed evidence capture and publication. Inputs can be account-mined evidence or an exact governed definition graph; keep these authority paths separate. Outputs are admitted input manifests, candidate files, validation receipts and an explicit review/publication disposition. [Orchestration](09-orchestration-and-reconstruction.md) governs lifecycle.

## Choose the contract

| Contract | Input authority | Output and limitation |
| --- | --- | --- |
| Account evidence mining | Owned queries and permitted profiles/meaning/values/interactions | Useful bounded context, with evidence and missingness; observed narrative is not reviewed business truth |
| Reviewed governed compile | Exact role/grant/policy/query/parameter/capability/definition/knowledge revisions | Candidate projected from admitted reviewed meaning; review-required is not published |
| Evidence capture | Exact footprint, requirements and typed observation/provenance envelopes | Canonical sealed evidence identity; sealing is not serving or durable knowledge binding |

Technical compilation can emit admitted SQL/contracts without a semantic model call. Semantic compilation requires the reviewed definitions and evidence its rules claim to use. A library helper, stored candidate or seal does not prove a connected runtime.

## Mine and pack evidence deliberately

Admit explicit query selections or choose defaults by declared recency, usage, semantic coverage and diversity. Expose selection policy/version and exclusions. Direct bounded rows are candidate evidence; vector annotations may rerank them without adding vector-only rows unless that behavior is explicitly chosen. Preserve qualified source/query/field identity through cross-query dedup.

Score optional evidence from compatible vector/lexical/recency/shape/consumer-role signals without presenting the mixture as confidence. Reserve required fields and per-query coverage. Sample values for coverage rather than frequency alone when appropriate: stratify frequency bands, keep stable ties and deduplicate exact identities. Counts remain counts; a count below one would need another interpretation rather than automatic percent formatting. Keep literal-eligible categories, metadata-only measures/time and sensitive fields distinct. Apply privacy policy to companions and every export projection, not only one values list.

Measure final byte/token limits after headers, section reserves, diversity passes and fallback additions. If required evidence cannot fit, return over-budget before model work. Caps are workload choices with documented selectors, not universal constants. Trace IDs/current week cannot influence output bytes if identical-input determinism is promised.

Staged authoring can produce audience/purpose, selected rule primitives and domain context. Each stage consumes a typed artifact and only admitted evidence. Rules carry stable primitive IDs and references; context cannot add new unsupported facts. A bounded model can propose prose, while deterministic validators establish shape/reference/coverage. Keep one authoritative quality/readiness result so a later score-only assignment cannot overwrite a prior hard failure. Audit fields are concise decision/change summaries with references, not semantic authority.

## Project and persist portable files

Use the same effective meaning adapters as runtime. Unwrap known scalar children, retain arrays and original unit tokens, and declare display normalization separately. An amount example is metadata unless the contract permits using it as a filter literal. Evidence-pack selection and final value-reference admission may use different budgets; name each policy and retain its coverage.

A portable manifest contains schema/renderer/compiler versions, input identity/hash, source/effective meaning revisions, required/excluded sections and per-file path/hash/byte count. Suggested files are overview, admitted schema/metric definitions, query SQL with parameter declarations, value evidence and invocation guidance for the chosen public runtime. Keep links package-contained. Files are not executable merely because their suffix is SQL or Markdown; invocation needs the consumer's authority.

Stage files and atomically replace the published manifest only after all required file hashes/coverage pass. Do not delete the previous complete tree before inserting its replacement. Concurrent-job idempotency is separate from source freshness: hash actual query/parameter/policy/effective evidence inputs, not only requested IDs. Rehydrating a stored tree, rebuilding a tree from current harvest and recompiling meaning are distinct operations with different identity claims.

## Bind reviewed meaning and capture evidence

Reviewed definitions declare purpose, metric algebra/numerators/denominators, natural/output grain, time/calendar, null semantics, units/conversions, scope predicates and join/fanout rules. References must fall within the admitted source footprint. Unknown grain cannot support preaggregation; a ratio needs reviewed component metrics and a snapshot needs latest/tie semantics. Source/policy ownership establishes authority; caller organization ID is an equality assertion only.

Bind exact grant/role/policy/query/parameter/definition/knowledge versions and recheck them before returning and publishing. Evidence selection is a whitelist of admitted profiles, meaning and values, not arbitrary previous prompts or unrelated sessions. One exact profile per required field and typed observed statistics are coverage conditions; hashes have meaning only when recomputed from retained canonical bytes.

A capture observation envelope needs stable observation ID, source/query/generation/population, evidence epoch, field/section, typed payload, producer attempt/input/output identity and content hash. Text-bearing observations include builder version and exact text/hash; vectors additionally bind the admitted encoder pair, role, dimensions, normalization/distance and actual vector hash. Required/optional/excluded/not-applicable requirements have explicit reasons. Recompute hashes, alias resolution, footprint membership, required rules and coverage before sealing canonically sorted observations. Validate finite vector shape; do not fabricate vectors or producer provenance.

An older companion object and a newer scalar-array capture format require a real typed adapter with honest input/provenance. A cast or invented hash cannot upgrade evidence. Preserve unsupported/unknown-preimage states. Sealing must fail on mixed generation, stale epoch, ambiguous field, policy-denied sample, missing required artifact or incompatible required vector.

## Finish the bridges

A complete serving design still needs capture→knowledge binding, durable input retention/reload, attempt fencing, compilation, review decision, manifest publication, authorization recheck, retrieval reader and consumer/citation delivery where advertised. Durable reload validates ownership, policy/role/knowledge currency, input hash/bytes, lease and expiry. Until these exist, return unavailable/review-required rather than advertise served semantic completion.

The controlled verifier checks canonical manifests, reviewed rule prerequisites, mixed/partial evidence rejection and an explicit missing-bridge refusal. Its snapshot declaration requires nonempty in-footprint `entity_keys`, an in-footprint `time_field`, explicit descending `time_order` for latest selection and nonempty `tie_breakers` with in-footprint fields and ascending/descending directions. Tie fields cannot merely repeat the entity keys or time field, and duplicate references are rejected. Missing keys/order/ties are rejected even when reviewed/latest/time metadata is present. These are declaration and reference checks; the example does not execute partitioned snapshot selection, prove source-key uniqueness or establish a complete null/equal-order policy. Those remain necessary execution-contract work. The verifier does not implement durable storage, grants, publication or a serving application.
